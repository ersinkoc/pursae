Build your own plugin

Back to Plugins

Anyone can build a plugin for their own site, also with an AI assistant such as Claude Code.

The developer documentation is written so that an AI can follow it step by step, and Pursae also exposes it to AI agents over MCP.

WebAssembly plugin (recommended)

A Go program compiled to WebAssembly. It runs in a sandbox, installs as a signed .zip package and survives core updates thanks to the stable plugin interface (ABI 1).

  1. Create the plugin and a signing key, then build the package:
pursae plugin new my-plugin
pursae plugin keygen -out mykey
pursae plugin build -dir . -key mykey.key -out my-plugin-1.0.0.zip
  1. Trust mykey.pub under Trusted Keys.
  2. Upload the .zip under Add Plugin › Upload Plugin.
  3. Activate the plugin and approve its permissions.

Native plugin

Go code compiled into the Pursae core itself, like the built-in Cache, SEO and Commerce plugins.

A native plugin cannot be installed from a .zip. It ships only as part of Pursae, so it is either contributed to Pursae and released in a core update, or built into your own fork.

Native plugins documentation

Share it with everyone

Send us the package (the .zip), a link to the source and a short description:

Email hello@pursae.com

Then open a topic in the Pursae forum describing your plugin:

Open the Pursae forum

After review it is signed with the Pursae key and appears under Add Plugin as an official plugin. Native plugins go the same way: they are reviewed for inclusion in the core.

Just for my own site

No submission is needed. Follow the documentation to write, sign and upload your plugin.

Core updates never change your installed plugins, because they live in the site's data folder and not in the Pursae binary. If a plugin cannot load after an update, you will be told on the Plugins screen.
